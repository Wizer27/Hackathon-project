# Парк «Сказка» — онлайн-стратегия

Сайт игры по кейсу 09 Всероссийского ИИ-хакатона 2026 и карта настоящего парка (усложнение).

| Страница | Что там |
|---|---|
| `index.html` | Сайт игры: liquid glass, анимации, герои, постройки, связь с реальным парком |
| `play.html` | 3D-тайкун от третьего лица на **настоящей карте парка 1:1**: директор ходит по реальным аллеям, восстанавливает 92 объекта (3D-модели) на их настоящих местах, кормит животных, чинит аттракционы, принимает гостей |
| `map/` | Мобильная карта парка (PWA) со «Сказочным паспортом» — коды из него дают бонусы в игре |

## Игра
- **3D** на Three.js (`vendor/three`, `world3d.js`): земля — карта парка (подробные тайлы `assets/world/`), камера — сверху сзади за директором.
  - Люди — реалистичные модели (Ready Player Me, Michelle) с анимациями Mixamo: ближайшие 40 гостей с разной одеждой и директор; дальние гости — простые фигуры (класс `Crowd`). Животные (альпаки, хаски, лисы, лошади), динозавры, деревья, кусты, фонари, урны — модели **Quaternius, CC0** (`assets/models/`, см. `LICENSE.md` там).
  - Земля — фото-покрытия по разметке карты: газон, плитка, асфальт, гравий, вода с отражениями (шейдер `realGround`). Небо — HDRI-панорама. Материалы и небо — **Poly Haven / ambientCG, CC0** (`assets/textures/`, `assets/sky/`). Скамейки — модель Poly Haven.
  - Аттракционы (колесо обозрения, карусели, горки, башни, вольеры, павильоны кафе и магазинов с вывесками) — процедурные модели в `world3d.js`.
  - Расстановка деревьев, фонарей, скамеек и кустов по карте — `tools/build_world.py` → `world-data.js`.
- **Карта** — официальная карта «Сказки», координаты объектов — из таблицы парка. Гости и директор ходят только по дорожкам (сетка проходимости собрана из цветов карты: `tools/build_game.py` → `game-data.js`).
- **Старт:** работают Колесо обозрения, карусель «Вальс» и Блинная. Остальное — свободные участки (`B`), директор идёт к участку и строит.
- **Управление:** WASD (Shift — бегом) или клик по дорожке — ходить; перетаскивание мышью — повернуть камеру; колесо — зум; `E` — покормить/починить рядом; `B` — участки. На телефоне — джойстик, поворот камеры пальцем, щипок.
- **Гости** входят через настоящие кассы, выбирают аттракцион по привлекательности, платят за билет. Настроение падает от мусора, голодных животных и сломанных аттракционов.
- **День** — 240 секунд (09:00–21:00), вечером темнеет. Потом итоги и утреннее событие от управляющей парком.
- **Экономика:** старт — 2500 монет. Каждая следующая постройка дороже на 15% (`INFLATION` в `game.js`). Каждый вечер — расходы: зарплаты 150 + обслуживание 5% от базовой цены каждой постройки в день. **Если деньги ушли в минус — банкротство, игра окончена** (кнопка «Начать заново»).
- **11 заданий**, рейтинг 1–5 звёзд, коды «Сказочного паспорта». Прогресс — в localStorage.
- **Модели «как в реальном парке»** генерируются ИИ по настоящим фото из таблицы парка: `MESHY_API_KEY=... python3 tools/generate_models.py` (стартовые и главные аттракционы; `--ids 28,15` — выбранные, `--all` — все). Готовые `.glb` кладутся в `assets/models/rides/` и прописываются в `manifest.json`; игра ставит их на реальные места вместо процедурных, в размер участка и входом к дорожке. Свои модели можно положить туда же вручную: `{ "28": "koleso.glb" }`.
- **Графика:** HDRI-небо, фото-покрытия по разметке карты, живая трава на газонах (≈140 тыс. травинок вокруг камеры, колышется на ветру), тени 4096, постобработка — SSAO (на компьютере), свечение огней, SMAA, виньетка.
- Экономика по категориям и отдельным объектам — в `catalog.json`.
- Иконки — [Lucide](https://lucide.dev) (ISC), в `icons.js`. Эмодзи не используются.

## Запуск

Локально:
```bash
python3 -m http.server 8000      # http://localhost:8000
```

### Деплой на сервер (Caddy)
Сайт статический — его раздаёт Caddy; бэкенд (FastAPI) работает рядом и доступен как `/api/...`.
```bash
# на сервере
sudo git clone https://github.com/Wizer27/Hackathon-project.git /srv/skazka
cd /srv/skazka
cp .env.example .env && nano .env                     # DATABASE_URL и ключи бэкенда
python3 -m venv venv && venv/bin/pip install -r requirements.txt
sudo chown -R www-data:www-data /srv/skazka

sudo cp deploy/skazka-api.service /etc/systemd/system/
sudo systemctl enable --now skazka-api                 # бэкенд на 127.0.0.1:8080

sudo cp deploy/Caddyfile /etc/caddy/Caddyfile
sudo nano /etc/caddy/Caddyfile                         # заменить skazka.example.com на свой домен
sudo systemctl reload caddy                            # HTTPS-сертификат Caddy получит сам
```
Обновление: `cd /srv/skazka && sudo -u www-data git pull && sudo systemctl restart skazka-api`.
Caddy не отдаёт наружу исходники бэкенда, `.env`, `tools/`, `.git`.

## Ведущий игры (утренние события)
Сейчас события берутся из сценария в `host.js`. Чтобы подключить своего ИИ-ассистента, замените `SkazkaHost.nextTurn` — формат запроса и ответа описан в комментарии в начале файла. Эффекты из ответа игра ограничивает (`LIMITS` в `game.js`). В `state.buildings` приходят id объектов карты (`map/data.js`).


## Карта парка (`map/`)

- **Карта** парка на основе официальной вертикальной карты: зум и перемещение пальцами, названия объектов при приближении.
- **113 объектов** из таблицы парка: аттракционы, зоны с животными, кафе, туалеты, кассы, фотостудии, остановки и парковки. У 110 есть фото.
- **Поиск** и **фильтры по категориям**.
- **Карточка объекта**: фото, категория, как найти, что рядом (аттракционы, кафе, туалет).
- **Кнопки 🚻 / 🍴** находят ближайший туалет или кафе.
- **«Сказочный паспорт»**: посетитель отмечается на настоящих аттракционах и получает награды (промокоды) в онлайн-стратегии «Парк Сказка». Так карта связана с игрой из кейса.
- **План дня**: список выбранных аттракционов.
- **Устанавливается на телефон** как приложение («На экран Домой») и работает **офлайн**: карта кешируется.
- Ссылки: `?id=28` открывает объект, `?checkin=28` ставит отметку. В реальном парке вторая ссылка будет QR-кодом у аттракциона.

Открывается по адресу `http://localhost:8000/map/`. Сборка не нужна: обычные HTML/CSS/JS и Leaflet (в `map/vendor/`).
Чтобы приложение устанавливалось на телефон и работало офлайн, сайт должен открываться по HTTPS (GitHub Pages, Netlify, Vercel и т. п.).

### Пересборка данных карты

`data.js`, `assets/map.webp` и `assets/photos/` генерируются из материалов парка:

```bash
pip install pymupdf pillow
python tools/build_data.py park.xlsx "Карта вертикальная.pdf"   # пишет в map/
```

Скрипт берёт из таблицы названия, категории, координаты и фото. В координатах вертикальной карты есть несколько опечаток, поэтому скрипт пересчитывает их из горизонтальной: карты отличаются только масштабом и сдвигом.
